Prompt-to-SDLC Studio

"Sebuah platform berbasis AI yang mengubah satu kalimat ide produk menjadi dokumen SDLC lengkap — PRD, arsitektur, user stories, API spec, TODO, dan rencana uji — secara instan tanpa backend atau autentikasi tambahan."

Masukkan satu kalimat ide produk → dapatkan seluruh artefak rekayasa perangkat lunak secara otomatis, ditenagai oleh IBM Bob AI.

⚡ Instan SDLC dalam hitungan detik
🤖 AI-Powered Didukung IBM Bob
📄 HTML-Only Zero backend, zero auth
🔍 Reviewed Output siap reviewer

📋 Product Requirements Document (PRD)

🎯 Tujuan Produk

Menyediakan alat bantu rekayasa perangkat lunak berbasis AI yang memungkinkan siapa saja — mulai dari founder, product manager, hingga developer — menghasilkan dokumen SDLC berkualitas produksi hanya dari satu kalimat ide, tanpa perlu keahlian teknis mendalam.

⚠️ Problem Statement

  • Menulis PRD, arsitektur, dan user stories memakan waktu berhari-hari bahkan berminggu-minggu.
  • Tim kecil / solo founder tidak memiliki bandwidth untuk dokumentasi menyeluruh.
  • Inkonsistensi antar artefak menyebabkan miskomunikasi antara bisnis dan engineering.
  • Tidak ada alat ringan (HTML-only) yang bisa dijalankan offline tanpa dependensi eksternal.

👥 Target Pengguna

  • Product Manager — butuh PRD cepat untuk sprint planning.
  • Solo Developer / Indie Hacker — ingin blueprint sebelum coding.
  • Startup Founder — perlu pitch material berbasis dokumen teknis.
  • Mahasiswa / Peserta Hackathon — deadline ketat, butuh scaffold cepat.

📐 Scope

✅ In-Scope

  • Input satu kalimat ide produk
  • Generate PRD otomatis
  • Diagram arsitektur CSS
  • 5+ User Stories terstruktur
  • Spesifikasi API & skema data
  • TODO list + timeline
  • Rencana uji & analisis risiko
  • Output HTML statis siap cetak

🚫 Out-of-Scope

  • Backend / server-side processing
  • Autentikasi / manajemen user
  • Database / penyimpanan persisten
  • Framework JS (React, Vue, dll)
  • CDN / font / gambar eksternal
  • CI/CD pipeline otomatis

✔️ Acceptance Criteria

  1. AC-01 Ide produk user di-echo verbatim di bagian Hero tanpa modifikasi apapun.
  2. AC-02 Semua 6 tab dapat diakses dan konten tiap panel konsisten dengan ide produk.
  3. AC-03 Halaman merender sempurna di viewport 360px – 1280px tanpa horizontal scroll.
  4. AC-04 Saat dicetak (@media print), semua panel tampil dan nav tab tersembunyi.
  5. AC-05 Zero error console; tidak ada dependensi JS, framework, atau resource eksternal.

📖 User Stories

US-01 Prioritas Tinggi

Sebagai seorang product manager, saya ingin memasukkan satu kalimat ide produk ke dalam platform, agar saya mendapatkan PRD lengkap tanpa harus menulisnya dari nol.

Kriteria Penerimaan

  • Ide di-echo verbatim di Hero section
  • PRD mencakup tujuan, problem, target user, scope, dan acceptance criteria
  • Output tersedia dalam ≤ 3 detik
US-02 Prioritas Tinggi

Sebagai seorang developer, saya ingin melihat diagram arsitektur yang jelas, agar saya memahami alur sistem sebelum mulai coding.

Kriteria Penerimaan

  • Diagram menampilkan minimal 4 node: Client → Bob → HTML → Reviewer
  • Tabel komponen mendokumentasikan teknologi dan peran tiap komponen
  • Diagram responsif di semua ukuran layar
US-03 Prioritas Menengah

Sebagai seorang tech lead, saya ingin melihat spesifikasi API dan skema data, agar tim backend dan frontend dapat bekerja secara paralel.

Kriteria Penerimaan

  • Minimal 3 endpoint dengan Method, Path, Input, dan Output
  • Minimal 1 skema data JSON terdokumentasi
  • Format konsisten dan mudah dibaca
US-04 Prioritas Menengah

Sebagai seorang QA engineer, saya ingin melihat rencana uji dan analisis risiko, agar saya dapat mempersiapkan test suite sebelum development selesai.

Kriteria Penerimaan

  • Minimal 5 skenario uji dengan expected result
  • Minimal 3 risiko dengan tingkat severity dan rencana mitigasi
  • Setiap risiko memiliki owner yang jelas
US-05 Prioritas Rendah

Sebagai seorang stakeholder non-teknis, saya ingin mencetak atau mengekspor dokumen SDLC ke PDF, agar saya dapat membagikannya kepada investor atau klien.

Kriteria Penerimaan

  • @media print menyembunyikan navigasi tab
  • Semua panel tampil saat dicetak
  • Layout print-friendly, tidak ada elemen terpotong
US-06 Prioritas Rendah

Sebagai seorang peserta hackathon, saya ingin mengakses studio ini dari perangkat mobile, agar saya dapat bekerja dari mana saja tanpa laptop.

Kriteria Penerimaan

  • Tampilan responsif di 360px (mobile) hingga 1280px (desktop)
  • Tidak ada horizontal scroll pada viewport manapun
  • Tab navigasi dapat diakses dengan mudah di layar sentuh

🔌 API & Spesifikasi Data

⚠️ Catatan: Platform ini adalah HTML-only tanpa backend. Spesifikasi API berikut merupakan kontrak antarmuka yang dapat diimplementasikan jika diperlukan integrasi di masa depan.

Daftar Endpoint

PUT /api/v1/document/:id Perbarui satu bagian dokumen (PRD, user stories, dll) { "section": "string", "content": "object" } { "updated": true, "sdlc": SDLCDocument }

⚠️ Analisis Risiko & Mitigasi

R-01 🔴 Tinggi

Konten Tidak Konsisten dengan Ide Produk

Dampak: PRD dan user stories tidak relevan dengan ide user, mengurangi nilai output.

Probabilitas: Sedang — bergantung pada kualitas prompt IBM Bob.

Mitigasi: Sematkan ide produk sebagai context anchor di setiap bagian dokumen; lakukan review konsistensi sebelum render final.

Owner: Product Manager

R-02 🟡 Menengah

Kompatibilitas Browser Lama

Dampak: CSS radio-tab trick tidak berfungsi di browser legacy (IE11 ke bawah).

Probabilitas: Rendah — target pengguna menggunakan browser modern.

Mitigasi: Tambahkan @supports query; sediakan fallback dengan semua panel visible di browser tanpa CSS :checked support.

Owner: Frontend Developer

R-03 🟢 Rendah

Keterbacaan pada Ukuran Layar Sangat Kecil (<360px)

Dampak: Tabel dan diagram bisa terpotong di perangkat dengan layar < 360px.

Probabilitas: Sangat Rendah — mayoritas smartphone modern ≥ 360px.

Mitigasi: Gunakan overflow-x: auto pada semua tabel; pastikan min-width tabel tidak melebihi 100vw.

Owner: QA Engineer
